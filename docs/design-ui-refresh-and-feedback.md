# UI/UX 개선 · 피드백 기능 설계

작성일 2026-11-23 · 대상 브랜치 `feat/ui-refresh`

## 1. 배경

배포된 화면을 직접 써 보고, 비슷한 서비스(Picker Wheel, Wheel of Names, Keamk, Teamru, 사다리 사이트, LoL 내전 밸런서)와 최근 작은 웹 도구의 디자인 경향을 조사했다. 지금 화면에서 걸리는 점은 다음과 같다.

| 문제 | 근거 |
|---|---|
| 템플릿 같은 인상 | 회색 바탕 위 카드 하나에 모든 입력을 담은 shadcn 기본 모양. 강조색 없이 검정 버튼만 있음 |
| 한글 글꼴 미지정 | 시스템 기본 글꼴로 나와 기기마다 모양이 다르고 굵기 대비가 약함 |
| **여러 줄 붙여넣기 버그** | 메신저에서 줄바꿈으로 된 명단을 붙여넣으면 한 줄 입력칸이 줄바꿈을 공백으로 바꿔 `철수 영희 민수` 한 명으로 등록됨 (배포본에서 재현) |
| 점수 입력이 비좁음 | 균형 모드에서 이름 칩 안에 점수칸이 끼어 있어 작고 누르기 어려움 |
| 조건 입력이 투박함 | 선택칸 3개 나열. 무엇을 만드는지 문장으로 읽히지 않음 |
| 모바일에서 주 버튼이 멀어짐 | 명단·조건이 길어지면 "팀 짜기"가 화면 아래로 밀림 |
| 결과가 밋밋하게 나타남 | 누르면 바로 바뀌어 "나눴다"는 순간이 없고, 결과로 시선이 가지 않음. 화면낭독기에도 알리지 않음 |
| 피드백 통로 없음 | 사용자가 불편을 전할 방법이 없어 개선 근거를 모을 수 없음 |

## 2. 디자인 원칙

1. **작전판 컨셉, 절제된 한 가지 강조색.** 따뜻한 종이색 바탕에 옅은 점 격자를 깔고, 주 동작(팀 짜기)에만 강조색을 쓰고, 팀 색은 별도의 작은 팔레트로 분리한다. 둘이 경쟁하지 않게 한다.
2. **카드는 결과에만.** 입력 영역은 평평한 면 위에 간격과 작은 제목으로 나누고, 카드는 팀 결과에만 쓴다. 템플릿 인상은 대부분 "전부 카드로 감싸기"에서 온다.
3. **움직임은 의미가 있을 때만.** 결과가 나타나는 순간 하나에 집중하고, `prefers-reduced-motion`이면 짧은 페이드로 대체한다.
4. **색에만 기대지 않는다.** 팀은 색과 함께 번호를 항상 표시한다(WCAG 1.4.1). 터치 대상은 최소 24px, 주요 버튼은 44px.
5. **새 의존성은 최소로.** 글꼴(CDN) 외에는 라이브러리를 늘리지 않는다. 대화상자는 네이티브 `<dialog>`를 쓴다.

## 3. 시각 체계

### 글꼴
- 본문은 **Pretendard Variable**, jsDelivr의 dynamic subset(`pretendard@1.3.9`)을 `index.html`에서 불러온다. 쓰는 글자 범위만 받아 가볍다.
- 로고·큰 제목·숫자(팀 번호, 팀 수)는 **Bricolage Grotesque**(Google Fonts)로 개성을 준다.
- 한글 본문에 `word-break: keep-all`(어절 중간에서 줄이 끊기지 않게), 줄 간격 1.6 안팎.
- 점수·인원 수에는 `tabular-nums`로 숫자 폭을 맞춘다.

### 색
- 중립색을 차가운 slate에서 따뜻한 stone 계열로 바꾸고, `--primary`는 **신호 주황**(라이트 `oklch(0.57 0.19 37)`, 다크 `oklch(0.75 0.15 52)`) 하나만 둔다. 보라·파랑 계열 강조색은 흔한 템플릿 인상이라 피했다.
- 배경에 22px 간격 점 격자(작전판)를 깐다. 다크 모드에서는 더 옅게.
- 팀 색(파랑·빨강·초록·주황·보라·청록)은 지금의 `TeamCard` 팔레트를 유지하되, 카드 위쪽 색띠와 번호 배지로 쓴다.

### 레이아웃
- **헤더**: 한 줄로 줄인다. 왼쪽 로고 표시 + "Team Maker", 가운데(모바일은 아래 줄) 탭 형태의 화면 전환, 오른쪽 피드백 버튼과 화면 모드 버튼.
- **본문**: 최대 폭 `2xl`, 회색 바탕+카드 대신 단일 면. 입력은 번호 붙은 단계로 나눈다.
  1. 참가자 2. 팀 구성(팀 수·균형 모드) 3. 조건(선택, 기본 접힘)
- **모바일 하단 고정 바**: 주 버튼 "팀 짜기 · 8명"을 화면 아래에 고정한다(안전 영역 여백 반영). 결과가 있으면 "다시 섞기"로 바뀐다. 데스크톱에서는 입력 아래에 일반 버튼으로 둔다.

## 4. 화면별 설계

### 4.1 랜덤 팀 짜기

**참가자 입력**
- 붙여넣기에 줄바꿈이 있으면 입력칸에 넣지 않고 바로 명단에 추가한다(버그 수정). 쉼표 구분은 지금처럼 유지.
- 칩은 입력칸 아래 별도 목록으로 둔다(입력칸 안 토큰은 화면낭독기 문제로 지양). 삭제 버튼 터치 영역을 24px 이상으로 키운다.
- 비어 있을 때 "예시로 채워보기" 같은 한 가지 행동을 주는 빈 상태 문구.

**팀 구성**
- 팀 수 스테퍼 옆에 실시간 요약: `8명 → 4명씩 2팀`, 나누어떨어지지 않으면 `3~4명씩 3팀`.
- 균형 모드를 켜면 참가자 칩이 **이름 | 점수** 행 목록으로 바뀐다. 점수칸이 넓어지고 숫자 키패드(`inputMode="decimal"`)가 뜬다.

**조건 — 문장형 입력**
- 먼저 종류를 고른다: `갈라놓기 · 붙여놓기 · 팀 고정` (세그먼트 버튼).
- 이어서 빈칸을 채우는 문장으로 보인다.
  - 갈라놓기: `[철수 ▾] 와(과) [영희 ▾] 는 다른 팀`
  - 팀 고정: `[철수 ▾] 는 [2팀 ▾] 에 고정`
- 등록된 조건도 문장으로 읽힌다: "철수와 영희는 다른 팀". 받침에 따라 조사(와/과, 은/는, 을/를)를 고르는 작은 함수를 둔다.
- 각 빈칸에는 실제 접근성 이름을 붙인다(문장형 폼의 흔한 실패 지점).
- 조건이 없으면 섹션을 접어 두어 처음 보는 사람의 부담을 줄인다.

**결과**
- 누르면 0.5초 이내의 짧은 섞기 연출 후 팀 카드가 차례로 나타난다(stagger). 동작 줄이기 설정이면 바로 페이드.
- 결과가 화면 밖에 있을 때만 결과로 스크롤한다. 상태 영역이 "2팀으로 나눴어요"를 알린다(WCAG 4.1.3).
  - 초점은 옮기지 않는다. 키보드로 "다시 섞기"를 연달아 누르는 흐름이 끊기지 않게 하기 위해서다.
- 카드: 위쪽 팀 색띠, `1팀` 배지, 인원·평균 점수, 이름 목록. 균형 모드면 상단에 `평균 차이 0.25` 요약.
- 동작: 다시 섞기 · 결과 복사 · 공유(Web Share API가 있으면 공유 시트, 없으면 숨김).

### 4.2 포지션별 팀 나누기
- 같은 시각 체계 적용. 포지션 이름 대신 짧은 배지(TOP·JGL·MID·ADC·SUP)와 두 입력칸.
- 결과는 A팀 vs B팀 두 카드, 가운데 `VS`.
- 기록은 접이식 섹션으로, 날짜 대신 "3분 전"처럼 상대 시간을 함께 보여준다. 빈 상태 문구 개선.

## 5. 피드백 기능

### 5.1 받을 곳 비교 (서버 없는 GitHub Pages 기준)

| 방식 | 설정 | 무료 한도 | 사용자 계정 | 개발자가 보는 곳 | 비고 |
|---|---|---|---|---|---|
| **Web3Forms** | 이메일 입력해 키 발급(~15분) | 월 250건 | 불필요 | 메일함 | 키는 공개용이라 코드에 넣어도 됨. 성공/실패 응답을 받을 수 있음 |
| GitHub 이슈 링크 | 이슈 양식 파일만 추가 | 무제한 | **GitHub 필요** | 저장소 Issues | 설정 0, 대신 일반 사용자는 거의 안 씀. 공개 저장소면 내용도 공개 |
| Tally | 폼 제작(~10분) | 사실상 무제한 | 불필요 | Tally 대시보드 | 외부 폼으로 이동. 앱 안 경험은 약함 |
| Formspree | ~15분 | 월 50건 | 불필요 | 메일·대시보드 | 한도가 작음 |
| Cloudflare Worker → 비공개 이슈 | 1~3시간 | 넉넉함 | 불필요 | 비공개 저장소 Issues | 가장 좋지만 손이 많이 감. 나중 단계로 |

**결정(2026-11-23): 외부 폼 서비스는 쓰지 않는다.** 지금은 GitHub 이슈로 받고, 나중에 여러 서비스가 함께 쓸 공용 수신 서버를 직접 만들면 그 주소만 등록해 앱 안에서 바로 보내도록 한다.
- 수신 주소(`VITE_FEEDBACK_ENDPOINT`)가 없는 빌드: 내용을 채운 GitHub 이슈 작성 화면을 새 창으로 연다.
- 수신 주소가 있는 빌드: 그 주소로 JSON을 POST한다. 실패하면 GitHub로 남기는 길을 함께 보여준다.
- 공용 수신 서버가 갖출 것: 허용 출처(CORS), 전송 횟수 제한, 캡차, 비밀 키 보관, 저장(DB/이슈)과 알림(메일).

### 5.2 화면
- 헤더의 **피드백** 버튼 → 네이티브 `<dialog>` 대화상자.
- 항목
  - 종류: `불편/오류 · 제안 · 기타` (세그먼트)
  - 내용: 여러 줄, 필수, 최대 1,000자, 남은 글자 수 표시
  - 연락처(선택, 수신 서버가 있을 때만): 답장이 필요할 때만. 적으면 개인정보 안내(수집 항목·목적·보관 기간·거부 가능)와 동의 체크가 나타난다. GitHub 이슈는 공개라 연락처 칸을 두지 않는다
  - 진단 정보 포함(기본 켬): 무엇이 전송되는지 그대로 펼쳐 보여줌
- 상태: 보내는 중 → "보냈어요, 고마워요" / 실패 시 이유와 "GitHub에서 남기기" 대안. 연속 전송은 30초 간격으로 제한.
- 스팸 방지: 숨은 허니팟 칸(수신 서버 모드). 서버 쪽 제한은 공용 수신 서버에서 한다.

### 5.3 전송 내용
- 보냄: 종류, 내용, 연락처(입력 시), 화면 경로, 앱 버전(빌드 시 커밋 해시 주입), 브라우저 정보, 화면 모드(설정/실제), 화면 크기
- **보내지 않음: 명단·점수·조건·기록.** 사용자가 직접 내용에 쓰지 않는 한 입력 데이터는 전송하지 않는다.

### 5.4 구조
- `lib/feedback.ts`: 전송 내용(`FeedbackPayload`) 만들기, 검증, GitHub 이슈 URL 만들기(URL 길이 제한 고려, 넘치면 잘라내고 전체 내용은 클립보드에 복사), 수신 서버 전송
- `components/FeedbackDialog.tsx`: 대화상자 UI
- `.github/ISSUE_TEMPLATE/feedback.yml`: 한국어 이슈 양식(`feedback` 라벨 자동)
- 수신 주소는 저장소 Variables의 `FEEDBACK_ENDPOINT`를 배포 워크플로가 `VITE_FEEDBACK_ENDPOINT`로 빌드에 넘긴다.
- 앱 버전은 `vite.config.ts`의 `define`으로 `GITHUB_SHA`(없으면 `git rev-parse`) 앞 7자리를 주입.

## 7. 범위 밖 (다음 단계 후보)
- 결과 이미지 저장, 팀 일부 고정 후 나머지만 다시 섞기, 명단 여러 개 저장, 결과 공유 링크
- 최근 결과와 겹치지 않게 섞기(Teamru의 중복 방지)
- 공용 피드백 수신 서버(별도 프로젝트) — 만들면 주소만 등록

## 8. 진행 순서와 검증
1. 시각 체계(글꼴·색 토큰·레이아웃·헤더) → 2. 랜덤 팀 화면 → 3. 포지션 화면 → 4. 피드백 → 5. 정리 작업
- 단계마다 lint·test·build, 라이트/다크 × 데스크톱/375px 스크린숏으로 확인
- 붙여넣기·조사 함수·피드백 전송 내용은 단위 테스트를 먼저 쓴다
- 커밋은 위 단계 단위로 나눈다
